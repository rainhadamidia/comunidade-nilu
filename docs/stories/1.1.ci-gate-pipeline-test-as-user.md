## Story

**As a** time técnico do ILUMINNARE,
**I want** um pipeline de CI que rode typecheck, lint e testes automaticamente em todo Pull Request e bloqueie o merge se qualquer um falhar, além de um esqueleto de suíte de impersonação (`test-as-user`) capaz de autenticar como usuário comum e rodar contra o Supabase real,
**so that** nenhuma migração dos Lotes 1-2 (RPCs de segurança, endurecimento de RLS) chegue à produção sem validação automática — hoje não existe CI nenhum (`QA-T01`) e o app tem ~0% de cobertura de testes (`SYS-09`), o que torna a vulnerabilidade de segurança ativa (`DBT-S01/S02/S03/S06`) indetectável até que alguém explore manualmente.

## Acceptance Criteria

1. Existe um workflow de CI (GitHub Actions) que roda automaticamente em todo Pull Request contra a branch principal, executando em sequência: `lint` → `typecheck` → `test`.
2. O workflow **falha e bloqueia o merge** se qualquer um dos 3 comandos retornar código de saída diferente de zero.
3. Existe o script `typecheck` no `package.json` (hoje não existe — só `lint` e `test`), usando `tsc --noEmit` sobre os 3 tsconfigs do projeto.
4. Existe um módulo esqueleto de suíte de impersonação (`test-as-user`) que consegue: (a) autenticar no Supabase via client `anon`/`publishable key` como um usuário de teste não-admin, e (b) rodar pelo menos 1 assert de exemplo (placeholder) contra uma tabela real, confirmando que a infraestrutura de auth-em-teste funciona ponta a ponta. Os casos de teste **reais** de segurança (negativos/positivos) são adicionados nas Stories 2-5, não aqui.
5. Existe um `docs/testing/test-as-user-guide.md` (ou seção equivalente) explicando: como criar/configurar o usuário de teste, como rodar a suíte localmente (`npm run test`), e como ela roda no CI.
6. Se o `lint`/`typecheck` atual já acusar erros pré-existentes no código (dívida herdada, não desta story), documentar essas falhas como exceção temporária registrada no Dev Notes desta story — **não** é obrigação desta story corrigir todo o código legado, apenas garantir que o gate funciona e bloqueia regressões **novas**.
7. `.env` é removido do controle de versão (`git rm --cached .env`) e o `.gitignore` já cobre `.env` (confirmar); a `VITE_SUPABASE_PUBLISHABLE_KEY` atual é rotacionada no painel do Supabase (ação humana — ver Dev Notes).

- Local: arquivos de teste de segurança ficam em `src/test/security/`.
- O teste placeholder desta story (Task 3) deve ser mínimo e determinístico — não depender de estado mutável de outros testes.
- `npm run test` deve incluir o novo teste automaticamente (padrão do vitest é pegar `**/*.test.ts` — confirmar que o glob do `vitest.config.ts` cobre `src/test/security/`).
- Critério de sucesso desta story: rodar `npm run lint && npm run typecheck && npm run test` localmente com saída verde antes de abrir o PR; e o mesmo comando rodando verde no Actions do PR.
